# HIG-aware design generation

1. State the target Apple platform, device classes, input methods, primary task, and product constraints.
2. Query relevant rules by category, platform, component, modality, and task.
3. Apply accessibility and privacy rules before platform, component, and visual guidance.
4. Design the main path plus empty, loading, error, denied-permission, and offline states.
5. Explain component choices, hierarchy, writing, interaction, state transitions, and relevant accessibility settings.
6. Cite rule IDs and official source URLs. Separate verified guidance, product decisions, exceptions, and unresolved review items.
7. Do not claim authoritative HIG compliance.
